# ADR-0021: 残高を変えたら、同じ数字を出す画面すべてを読み直す

- 日付: 2026-08-02
- 状態: 承認

## 文脈

残高は 2 つの応答に載る。

- 家族の詳細（`/api/families/{id}` の `memberships[].balance`）… ダッシュボード・
  ナビゲーション・家族設定がこれを見る。取得は 1 回にまとめてあり
  （`FamilyContext`）、ログイン後の画面が同じものを共有する。
- 台帳（`/api/families/{id}/ledgers/{id}` の `balance`）… 台帳の画面が
  残高と履歴のために取る。

台帳の画面はポイントを記録した後、自分の応答だけを読み直していた。共有している
家族の応答はログイン直後の 1 回きりなので、加算してダッシュボードへ戻ると、
そこだけ古い残高が残る。ブラウザを再読込するまで直らない。

同じことが端末をまたいでも起きる。ホーム画面から開いた PWA はタブが何日も
生きたままで、もう一人の親が自分の端末で足したポイントは、こちらの画面に
いつまでも出てこない。

## 決定

1. 残高を変える操作（加算・消費・打ち消し）の後は、**変えた画面と
   `FamilyContext` の両方**を読み直す。
2. 画面が手元に戻ってきたとき（`visibilitychange` で `visible` になる・`online`）
   にも読み直す（`useRefreshOnReturn`）。裏に回っているあいだは読み直さない。
3. 読み直しに失敗しても、すでに出している残高は消さない。失敗はトーストで伝え、
   台帳は取得時刻で古さを示す（ADR-0015）。

## 理由

- **残高の出所を 1 つにまとめる案は採らない**。台帳の応答は履歴と `can_modify`
  を伴い、家族の応答は「見える範囲の子」にだけ `balance` を載せる（ADR-0009）。
  同じ数字でも可視範囲と付随する情報が違うので、どちらかをもう一方から導けない。
  出所が 2 つあることは受け入れ、**変えたら両方読み直す**という規則で揃える。
- **応答から画面側で残高を足し込む案は捨てた**。打ち消し・別の端末からの記録・
  サーバー側の判断を画面が再現することになり、正しさの出所が 2 つになる。
  読み直しは往復が 1 回増えるだけで、正しさはサーバーに残る。
- **ポーリング・WebSocket は採らない**。家族という単位と更新の頻度に対して、
  常時接続の運用（再接続・認証・切断の見せ方）が見合わない。「見に戻ってきた
  ときに読み直す」で、利用者が見ている瞬間の値は新しい。
- **失敗で表示を消さない**。手元に戻った瞬間の一時的な不通で読めていた履歴まで
  消えると、原因の分からない空の画面になる。家族の側はさらに悪く、残高も子への
  入口も消えるため、家族から外されたようにしか見えない。「読めなかった」
  （`failed`）と伝えるのは**出せるものが何も無いとき**だけにし、それが
  「所属していない」を意味しないのは従来どおり。

## 影響

- 記録 1 回あたりの API 呼び出しが増える（台帳 + 家族の一覧・詳細）。
- 残高を出す画面を新しく作るときは `FamilyContext` から取る。画面ごとに
  家族を取り直さない（取得を 1 回に保つ前提が崩れる）。
- 家族の応答に載る情報（参加者・残高・可否）を変える操作は、どの画面から
  行っても `useFamily().reload()` を呼ぶ。呼び忘れると、その画面だけが新しく
  なる。
