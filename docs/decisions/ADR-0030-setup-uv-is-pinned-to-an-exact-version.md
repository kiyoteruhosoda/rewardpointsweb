# ADR-0030: `setup-uv` だけ完全な版で固定する

- 日付: 2026-09-04
- 状態: 承認

## 文脈

CI の実行に注釈が出ていた。

```
Node.js 20 is deprecated. The following actions target Node.js 20 but are being
forced to run on Node.js 24: astral-sh/setup-uv@v6.
```

GitHub のランナーは Node 20 を落とし、`node20` を要求する action を Node 24 で
**強制的に**動かしている。互換のための猶予であって、action 側が Node 24 で試して
いる保証は無い。猶予が切れれば止まる。**注釈にしか出ない**ので、チェックは緑のまま
気付けない。

このリポジトリで `node20` を要求していたのは `astral-sh/setup-uv@v6` だけ
（`actions/checkout@v6` と `actions/setup-node@v6` は既に `node24`）。

上げるにあたって困ったのは、**`setup-uv` が v8 以降 `@v8` のような動く major タグを
発行しなくなった**こと。理由は上流が明記している —— 動くタグは差し替えられるため、
`tj-actions` の事件のようなサプライチェーン攻撃の入口になる。

## 決定

**`astral-sh/setup-uv` を `@v10.0.1` と完全な版で固定する。** 他の action は
これまでどおり動く major タグ（`@v6` など）を使う。

**なぜここだけ書き方が違うのか**をワークフローにコメントで残す。

## 理由

**強制実行は仕様ではなく猶予。** 「今は動いている」を根拠に据え置くと、猶予が
切れた日に CI が止まる。予告は注釈にしか出ない。

**上流が major タグを出していないものを、無理に揃えない。** 見た目を `@v10` で
揃えるには、こちらでタグを作るか古い版（`@v7`）に留まるしかない。前者は上流が
避けたかった「差し替えられるタグ」を自分で復活させることになり、後者は結局
Node 20 の版に据え置くことになって目的を失う。**書き方の不揃いは、固定の強さが
違うという事実の反映**であって、直すべき乱れではない。

**全部を完全な版で固定する案は採らない。** 一貫はするが、`checkout` や
`setup-node` まで手で追うことになる。動く major タグを出している action は、
上流がその運用（パッチを自動で配る）を選んでいるのだから、それに乗る。

親テンプレート `fastapitemplate` も同じ判断をしている（あちらの ADR-0030）。

## 影響

- **`setup-uv` の版を上げるのは手作業になる。** `@v10.0.1` は自分では動かない。
- **`prune-cache` の既定が `false` になった**（`setup-uv` v9 の破壊的変更。PyPI の
  負荷を下げるため）。Actions のキャッシュ使用量は増えるが、上限まで LRU で回る
  だけなので明示的な設定は足さない。
- **`v6 → v10` は破壊的変更を 3 つまたぐ**が、このリポジトリはどれにも触れていない
  —— 廃止された `server-url` 入力（v7）と旧 `manifest-file` 形式（v8）は未使用、
  `pull_request_target` / `workflow_run` / `release` でのキャッシュ自動無効化（v10）は
  該当するトリガーを使っていない。
