# ADR-0062: 「戻る」で戻ったら、見ていた位置へ戻す（全画面・雛形 ADR-0107 の写し）

- 日付: 2026-11-17
- 状態: 承認

## 文脈

家族の一覧・家族の詳細・台帳などから別の画面を開き、ブラウザの「戻る」で戻ると、いつもいちばん上から
表示される（nolumiatask #1063 の横展開・#1079）。この画面もデータが届くまで本文を描かないので、
ブラウザが位置を戻す瞬間はページが短く、先頭に切り詰められる。雛形 fastapitemplate が ADR-0107 で
外枠だけで直した。それを写す。

## 決定

1. 雛形の `frontend/src/hooks/useHistoryScroll.ts` を写し、外枠（`App`）で `useHistoryScroll()` を
   1 回呼ぶ。中身と理由は雛形の ADR-0107 と同じ（履歴の 1 件ごとに `sessionStorage` へ控え、
   戻る・進むではページの高さが届くのを待って戻す。最大 5 秒・利用者が動かしたらやめる。リンクで
   別の画面を開いたら先頭から）。
2. この app 固有の手当ては入れない。

## 理由

- **一覧はどれも窓ごと流れる。** `overflow` の箱は横に流す表の枠（`.table-scroll`。縦は窓のまま）と
  狭い画面の横のメニューだけ。
- **自前で位置を動かす所（`scrollTo` など）も、後読み（下へ送ると足していく一覧）も無い。**
- **台帳の履歴のページ送りは URL に載せない。** 履歴は台帳を読んだ全行を画面の中で区切っており、
  書いたら 1 ページ目へ戻す（新しい行が先頭に来る）。履歴の行から別の画面を開く形ではなく、
  台帳から開くイベント・ガチャのリンクは見出しの横にあるので、戻ったときに履歴の何ページ目かが
  効く場面は少ない。

## 影響

- 控えは `sessionStorage` の `history-scroll:` で始まる名前に溜まる（タブを閉じれば消える）。
- リンクで別の画面を開くと先頭から出るようになった（今までは前の画面の位置が残っていた）。
- 台帳の履歴を 2 ページ目以降まで送ってから別の画面へ行き「戻る」と、1 ページ目のその位置に出る。
