# ADR-0011: メールアドレスを持たない子アカウントの認証方式

- ステータス: 承認
- 日付: 2026-08-01
- 関連: ADR-0009（家族グループを共有単位とする）
- 対象: `bounded_contexts/account_security/`, 認証基盤

## コンテキスト

ADR-0009 において、子ども本人もアカウントを持ち `FamilyMembership(role = child)` として
家族に所属する構造を採用した。子ども本人が自分の端末からログインし、
自分の残高と履歴を参照することを前提とする。

一方、既存の認証基盤はメールアドレスを識別子とする前提で構築されている。

- ログイン識別子がメールアドレス
- パスワードリセットが SMTP によるメール送信に依存
- 初期管理者が `admin@example.com` として作成される

子どもは年齢によってメールアドレスを持たないことが多く、
また保護者の管理下にない外部メールサービスの利用を前提にすることは望ましくない。
子どものメールアドレスを収集しない設計は、個人情報の取り扱いを軽くする点でも有利である。

## 決定

アカウントの識別子をメールアドレスから分離し、メールアドレスを任意項目とする。

### 識別子

- `account.username` を追加し、ログインの識別子とする（UNIQUE）
- `account.email` を nullable に変更する。設定されている場合は従来どおり通知・リセットに用いる
- 既存アカウントは移行時に `username` へメールアドレスの値を設定する

### 子アカウントの作成

子アカウントは子ども自身では作成できない。

1. 親（`owner` または `parent`）が `role = child` の `FamilyMembership` を作成する
   （この時点でアカウントは未紐付け）
2. 親が招待コードを発行する（`family_invitation.target_membership_id` に上記 membership を指定）
3. 子が自分の端末で招待コードを入力し、`username` とパスワードを設定してアカウントを作成する
4. アカウントと membership が結び付き、ポイント台帳が参照可能になる

招待コードはハッシュ化して保存し、有効期限と使用済み日時を持つ。

### パスワードの変更とリセット

メールアドレスを持たないアカウントでは SMTP 経由のリセットが成立しないため、
経路を用途で分離する。

| 経路 | 実行者 | 条件 | 動作 |
| --- | --- | --- | --- |
| パスワード変更 | 本人 | 現行パスワードを入力できる | 新パスワードを設定 |
| パスワードリセット | 本人 | `email` が設定済み | 従来どおり SMTP でリセットリンクを送付 |
| パスワードリセット | 親（owner / parent） | 対象が同一家族の `role = child` | 一時パスワードを発行 |

親による一時パスワード発行は次の条件を伴う。

- 発行された一時パスワードには有効期限を設ける
- 一時パスワードでのログイン後、パスワードの変更を完了するまで他の操作を許可しない
- 発行の事実（発行者・対象・日時）を構造化ログおよび `log` テーブルに記録する
- 対象が `role = child` の場合に限る。親から親へのリセットは許可しない

### 二要素認証・パスキー

TOTP および WebAuthn はメールアドレスに依存しないため、そのまま利用できる。
子アカウントでの利用は任意とし、既定では有効化しない。

パスキーは、パスワードを記憶する必要がない点で子どもとの相性が良い一方、
端末を家族で共有する場合には他の家族の資格情報と混在するため、既定の手段としては採用しない。

## 結果

### 良い点

- 子どものメールアドレスを収集せずにシステムを運用できる。
- パスワードを忘れた場合の回復経路が家庭内で完結し、外部サービスに依存しない。

### トレードオフ

- 認証系の各フローに、メールアドレスの有無による分岐が入る。
  影響範囲はサインアップ、ログイン、パスワードリセット、通知送信、二要素の回復手段に及ぶ。
  本 ADR の適用前に、既存実装における `email` への依存箇所を洗い出す必要がある。
- メールアドレスを持たないアカウントは、システムからの通知メールを受け取れない。
  通知は PWA の Web Push または画面内表示で代替する。
- 親が子のパスワードをリセットできることは、親が子のアカウントとして操作しうることを意味する。
  台帳の操作履歴には操作者の membership が記録されるため（ADR-0010）、
  その経路での操作も追跡可能である点をもって許容する。

## 検討した代替案

### 子ども専用のログインを設けず、親端末上の PIN 切替のみとする

実装は最も軽い。ただし子どもが自分の端末から自分の残高を確認できず、
「自分のポイント」という感覚が生じにくい。本システムの目的と整合しない。

### 子アカウントにダミーのメールアドレスを割り当てる

既存実装への変更が最小で済むが、到達不能なアドレスがデータとして残り、
リセットや通知の失敗が実行時まで顕在化しない。問題の先送りにあたる。

### 閲覧専用リンク（トークン付き URL）で残高を共有する

アカウント管理が不要になる一方、リンクの漏洩がそのまま閲覧権限の漏洩となり、
兄弟間の非公開（ADR-0009）を担保できない。
