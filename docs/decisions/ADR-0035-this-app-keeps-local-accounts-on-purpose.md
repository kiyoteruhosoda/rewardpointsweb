# ADR-0035: このアプリはローカル口座を**意図して**持つ（そして入れる手段を数える）

- 日付: 2026-09-14
- 状態: 承認

## 文脈

このアプリには**認証系が 2 つある。**

- IdP（assay）側 —— パスワード・TOTP・パスキー・認証ポリシー（`require_mfa` など）
- このアプリ側 —— `account_security` コンテキスト（パスワード・TOTP・パスキー）

idp の ADR-0049 G1 が「最大のギャップ」として挙げているのがこれである。影響は
「二重持ち」では済まない。

- **IdP 側で多要素を必須にしても、このアプリのローカルログインには一切掛からない。**
- **パスキーの解除も IdP の分しか効かない。**
- ⚠ **利用者が「入れる手段」の一覧が、どこにも無い。**

そして ADR-0049 はこう書いている ——**「いまはどちらとも決めていない状態が既定に
なっている」**。決めていないこと自体が問題で、片付け方は 2 通りある。

1. **SSO 専用にする。** `account_security` を落とし、break-glass を 1 口座だけ残す。
2. **ローカル口座を意図して持つ。** その旨を ADR に書き、認証系が 2 つあることを
   前提にした運用（棚卸し・多要素の強制）をこちら側にも用意する。

## 決定

**このアプリは 2 を選ぶ ——ローカル口座を意図して持つ。** そのうえで、

1. **「入れる手段」を数えて画面に出す。** `GET /api/admin/users` の `entrances`
   （パスワード / 二要素認証 / パスキーの本数 / 結び付いている IdP）。
   材料は**それぞれのコンテキストに聞く**（パスワードは `users` の列、TOTP と
   パスキーは `account_security`、結び付きは `identity_federation`）。
2. **利用者ごとに「ローカル認証を持たない」を表せる**（ADR-0034 の `password_hash`）。
   アプリ全体の栓は `LOCAL_LOGIN_ENABLED`（ADR-0029）。**この 2 つは別物**で、
   前者は行ごと、後者はアプリ全体である。
3. **この ADR が、その宣言である。** 雛形（fastapitemplate）から起こしたアプリは
   作った時点でどちらかを自分の ADR に書くことになっている（雛形の ADR-0039）。
   このアプリの答えを、ここに置く。

## 理由

**このアプリは 1 を選べない。** ⚠ **子どものアカウントはメールアドレスを持たない**
（ADR-0011）。IdP に口座を持てない利用者が最初から居るので、ローカルの入り口を
取り上げると**その人たちが入れなくなる**。パスワード（親が発行する一時パスワードを
含む）とパスキーは、このアプリの主の入り口である。SSO は**後から足した追加の入り口**
で、親のように IdP に口座がある人だけが使う（ADR-0029）。

**2 を選んだ以上、宿題は「棚卸し」である。** ADR-0049 が挙げる 3 つの影響のうち、
最初の 2 つ（多要素の強制・パスキーの解除）は**どちらの認証系にも効かせようがない**
——別の認証系なのだから、それぞれで操作するのが正しい。だが 3 つ目
「入れる手段の一覧がどこにも無い」は、**単に無いだけ**だった。作れば埋まる。

**数えるのは「開いている口」であって「使われた口」ではない。** 監査ログには
「どの入口で入ったか」が残る（ADR-0029 決定 1）。あれは事後の記録で、
**いま何本開いているか**は答えない。止めるべき口を探すときに要るのは後者である。

### 検討して捨てた案

- **このアプリを SSO 専用にする。** 上のとおり、⚠ **メールアドレスを持たない
  利用者が入れなくなる**。選べない。
- **一覧を 1 人ずつ引く口にする**（`GET /api/admin/users/{id}/entrances`）。棚卸しは
  全員分を並べて初めて意味を持つ。1 人ずつだと画面が利用者の数だけ問い合わせる。
- **IdP 側の多要素も一覧に混ぜる。** 混ぜられない ——このアプリは IdP の認証器を
  知らないし、知ろうとすると IdP の管理 API への依存が 1 本増える。⚠ **混ぜられない
  ことこそが「認証系が 2 つある」の実体**なので、そのまま見せる。

## 影響

- **`GET /api/admin/users` の応答に `entrances` が増える**（一覧・作成・更新のいずれも）。
- **画面（S8 ユーザー管理）に「入れる手段」の列が増える。** 表示だけで、ここからは
  取り上げられない（取り上げ方はそれぞれの口の側にある）。
- ⚠ **多要素の強制はまだ無い。** IdP 側で `require_mfa` を掛けても、こちらの
  ローカルログインは素通しのままである。`docs/Progress.md` の T3。
- **利用者ごとに「ローカル認証なし」は表せる**（ADR-0034 の `password_hash`）。
  アプリ全体を SSO 専用にはできないが、**親だけ SSO 専用**にすることはできる。
