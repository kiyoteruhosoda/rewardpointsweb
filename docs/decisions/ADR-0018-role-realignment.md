# ADR-0018: アプリケーションロールをアクターに揃える（member=親 / guest=子 / manager=運用者）

- ステータス: 承認
- 日付: 2026-08-01
- 関連: ADR-0017（家族作成時の昇格）を置き換える。ADR-0013 の「除名後のアカウント」、
  ADR-0014 の「昇格先のロール」を改める。ADR-0009 の認可表・二段構えの認可は不変。
- 対象: `shared/domain/auth/`、`bounded_contexts/reward_points/`

## コンテキスト

語彙が三重にねじれていた。ADR の文章は親を「メンバー」、子を「ゲスト」と呼ぶのに、
実装は親に `manager`、子に `member` を割り当て、`guest` はどこにも使われない
テンプレートの名残だった。この結果、

- 管理画面で大人を `member` として登録すると家族を作れない（PR #21 の発端）
- 「家族機能に一切触れないアカウント」（旧 guest）という、この システムに
  想定利用者の居ない層が残っていた

システムのアクターは「システム管理者・親・子」だけである。アカウントは管理者が
作り（セルフサインアップは無い）、子のアカウントは招待の受諾で初めて生まれる。

## 決定

### ロール = アクター

| ロール | アクター | scope |
|---|---|---|
| `admin` | システム管理者 | **家族・ポイント以外の全部**（ユーザー・ロール・権限・設定・ログ） |
| `member` | 親（メンバー） | `family:view/manage`・`point:view/manage` + 画面系 |
| `guest` | 子（ゲスト） | `family:view`・`point:view` + 画面系（閲覧のみ） |
| `manager` | 運用者 | `item:*`・`log:view` + 画面系。**家族機能とは無関係** |

家族・ポイントは家庭の当事者（member / guest）の領分で、システム管理者は
関与しない。admin の仕事はアカウントとシステムの管理であって、他人の家庭の
台帳を見ることではない。

家族内ロールとの対応（`sql_account_directory.py`）: owner / parent → `member`、
child → `guest`。`manager` は家族のフローでは一切割り当てない。
管理画面のユーザー作成のデフォルトは `member`。

### 家族の作成は保護者の scope 一式

作成は「一人前の保護者になる」操作なので、`family:view` / `family:manage` /
`point:view` / `point:manage` の全部を要求する。親（member）は最初から作れる。
子（guest）・admin・一部の scope しか持たないカスタムロールは scope で止まる —
閲覧も記録もできない owner を生まないため。ADR-0017 の「`family:view` で入れて
作成時に昇格」は不要になったため廃止する。

### 子のライフサイクル

子アカウントは家族の参加としてだけ存在する。**未所属の guest は運用上存在しない**。

- **誕生**: 招待の受諾（redeem）で guest として生まれる。子の招待コードは
  redeem 専用で、既存アカウントの受諾（accept）では使えない
  （`child_invitation_requires_signup`）— 除名の後始末（アカウント削除）が、
  独立に存在するアカウントを巻き込まないための保証でもある
- **卒業**: 独立（ADR-0014、親の指示 + 本人の承認）で guest → `member` へ昇格し、
  所属なしのメンバーになる。昇格の実装（`grant_guardian_permissions` — 保護者の
  scope を全て持つ場合はロール構成へ触れない）は ADR-0017 から引き継ぐ
- **除名**: 台帳が空の場合に限り owner が外せる（ADR-0013）。結び付いた
  アカウントは**参加と一緒に削除する**。ADR-0013 の「除名→初期状態に戻った
  アカウント」は本 ADR が置き換える — 記録の無い子の縁切りに、ログインだけ
  できて何も持たないアカウントを残さない。台帳が空のときだけなので、履歴が
  消える経路にはならない（ADR-0010 と整合）
- 親（parent）の招待を使えるのは保護者になれるアカウント（member）だけ。
  guest が使うと `guardian_account_required` で断る（トランザクションごと
  巻き戻るため、招待コードは消費されない）

## 理由

- ADR-0013 の「所属していないアカウントだけが作れる」を、ロールの語彙ごと
  実装に一致させた。scope の付与・対応表・ADR の文章が同じ言葉で読める。
- 検討した代替案: ロール名の改名（`member` → `guardian` 等）。名前と実態は
  一致するが、ADR の語彙（メンバー/ゲスト）との対応は結局ずれたままになる。
  既存のロール名を実態の側へ寄せる方が変更が小さい。
- 子の防壁は従来どおり二段構え: scope（guest に manage 系なし）+ 家族内
  ロール（child は台帳を変更できない）。

## 影響

- マイグレーション `0010_realign_roles` が付与と割り当てを引き直す:
  子（child の参加を持つアカウント）は member → guest、manager 保有者は member へ。
- scope は JWT に焼き込まれているため、既存セッションは再ログインまで旧 scope の
  まま動く（旧・子ども用 member は閲覧のみなので、意図しない権限拡大はない）。
- 管理者が手動で guest を作ること自体は禁じない（運用外だが、scope で家族の
  作成・親招待の受諾は閉じている）。
