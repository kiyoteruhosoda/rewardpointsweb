# ADR-0051: ログインの往復で行き先（経路とクエリ）を落とさない

- 日付: 2026-10-21
- 状態: 承認

## 文脈

未ログインでログイン必須の画面を開くと、`RequireAuth` がログイン画面へ送る。このとき行き先を
持たせずに `/login` へ送っていたため、SSO・パスワード・パスキーのどれで入っても着地（`/`）へ
戻された。ログイン画面が行き先にしていたのは招待コード（ADR-0025）の経路だけで、サーバ側の
SSO の入口（`GET /api/auth/sso/login?redirect_to=`）が行き先を受けて往復の後に返す作りは
使われていなかった。

共有された深いリンク（台帳の画面など）を開いた人は、ログインした後にもう一度その URL を
開き直すしかなかった。元テンプレートの fastapitemplate は同じ不具合を ADR-0055 で直している。

## 決定

- `RequireAuth` はログイン画面へ送るとき、今の経路とクエリを `?redirect_to=` に載せる
  （着地から来たときは付けない）。
- ログイン画面はその値を絞って（`services/returnTo.ts`）、SSO の入口へ渡し、
  パスワード・パスキーで入ったときもそこへ遷移する。
- **招待コードを持って来たときは、従来どおりコードの行き先を先にする**（パスワード・パスキーは
  `/families#code=…`、SSO は `/families`）。
- 絞る規則はサーバの `RedirectTarget.parse` と同じ（自サイト内の絶対パスだけ）。加えて
  サーバが受け取る上限の 255 文字を超えるもの・改行を含むものは着地へ倒す。

## 理由

- 招待コードを優先するのは、コードを持って来た人の目的が「家族に入ること」だから。
  行き先を優先すると、コードを持っているのに参加の欄に辿り着けない状態に戻る。
- クエリ名はサーバの入口がすでに受けている `redirect_to` に揃えた。
- 長すぎる値をそのまま渡すと、入口が 422（JSON）を返して画面が止まる。行き先を失うほうが、
  ログインできないよりましである。
- URL の断片（`#…`）は行き先に含めない。断片で運ぶ値（招待コード・表示端末の確認コード）は
  それぞれの仕組み（ADR-0025 / ADR-0047）が預かる。`redirect_to` はサーバへ届くので、
  断片を載せると平文でログに残る。

## 影響

- サーバ側の変更は無い。
- 古い版の画面を Service Worker が持っている端末では、新しい版に入れ替わるまで直らない。
