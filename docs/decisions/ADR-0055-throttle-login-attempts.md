# ADR-0055: ログインの失敗を宛名ごとに数え、上限を超えたらしばらく断る

- 日付: 2026-10-30
- 状態: 承認

## 文脈

パスワードのログイン（`POST /api/auth/login`）は誰でもログインなしで叩け、何度でも試せた。
子どもの口座は /join で作るパスワードの口座で、8 字以上というだけなので、ユーザー名が分かれば
外から総当たりできた。再設定の申し込み（`forgot-password`）も、メールアドレスの無い口座
（＝子ども）にだけ `ask_guardian` を返すため、子どものユーザー名が実在するかを外から確かめられた
（2026-10-29 の点検、task #733）。雛形（fastapitemplate）は ADR-0058 で塞いでいた。

## 決定

雛形の ADR-0058 の作りをそのまま持ってくる。

- 数える単位は**送られてきた宛名**（ユーザー名。大文字小文字と前後の空白は揃える）。実在するアカウントとは結ばない。
- 窓（`LOGIN_FAILURE_WINDOW_SECONDS`、既定 900 秒）の中で上限（`LOGIN_MAX_FAILURES`、既定 5 回）まで失敗したら、
  `LOGIN_LOCK_SECONDS`（既定 900 秒）のあいだ **429 `too_many_attempts`** で断る（`Retry-After` と
  `retry_after_seconds` で待ち時間を返す）。正しいパスワードでも断る。
- パスワードの間違い・二要素のコードの間違いは同じ数え上げに入れる。正しく入れたら忘れる。
- 再設定の要求は別の籠で、**成功も数える**。
- 控えは DB の `login_attempts` に置く。断り始めたことはログに `login_locked` で残す。
- 未知の宛名・パスワードを持たない利用者でも、ダミーのハッシュと照合して応答時間を揃える。
- 再設定の申し込みは、メールアドレスの無い口座にも実在しない名前と同じ応答（`accepted`）を返す。
  親に一時パスワードを頼む案内（ADR-0011）は、画面が「送りました」の文面に常に添える。
- パスワードは 128 字までに切る（ログインなしで届く口で大きな文字列を照合させない）。

1 つの IP からの洪水は、前段の nginx の `limit_req`（deploy-repo の `rewardpointsweb-*/20-config.yaml`）が止める。
宛名ごとと IP ごとは役割が違うので両方置く（deck と同じ 2 段構え）。

## 理由

- 実在するアカウントだけを数えると、断られるかどうかで存在が分かってしまう。
- プロセスのメモリではなく DB に置くのは、Gunicorn が複数ワーカーで動くため（ワーカーの数だけ試せる）。
- 失敗の記録は 401 と一緒に返る（例外で抜ける）ので、リクエストの DB セッションに書くと rollback で
  消える。控えは自前の短いセッションで commit する。
- 401 に紛れ込ませないのは、断られていることが分からないと正しいパスワードを入れても弾かれ続けて
  「忘れた」と誤解し、再設定へ流れるため。

## 影響

- ユーザー名を知っている人は、わざと間違えてその人をしばらく締め出せる（妨害）。上限と断る長さは管理画面の
  設定で変えられる。`LOGIN_MAX_FAILURES=0` で数えない（本番で 0 にしない）。
- 再設定の画面は、メールアドレスの無い口座かどうかを見分けられなくなった。案内は文面で常に出す。
- パスキーと SSO のログインは対象外（パスワードもコードも無いので、総当たりの的にならない）。
- 移行は表を足すだけ。
