# ADR-0045: 新しい版はすぐ有効にし、開いている画面には知らせる

- 日付: 2026-10-03
- 状態: 承認（ADR-0044 を置き換える）

## 文脈

ADR-0044 で「新しい Service Worker は待機させ、知らせを押したら入れ替える」作りにした。
使ってみると分かりにくかった。

- **リロードしても新しい版にならない。** 待機中の Service Worker は、ふつうのリロードでは
  有効にならない（押すか、アプリを完全に閉じるしかない）。「リロードじゃダメ？」と聞かれた。
- 前の作り（autoUpdate）からの移行で画面が古いまま止まり、一度きりの移行処理
  （`sw-migration.js`）を足す羽目になった。

## 決定

- 新しい Service Worker は **配られたらすぐ有効にする**（`skipWaiting` / `clientsClaim`）。
  リロードすれば必ず新しい版になる。
- 開いている画面には、制御が新しい Service Worker へ移った（`controllerchange`）ときに
  「新しい版があります。［再読み込み］」を出す。押したら再読み込みする。
- 登録は自前（`services/appUpdate.ts`）で行い、プラグインの登録コード（有効になった瞬間に
  黙って再読み込みする）は使わない。更新の確認は 30 分ごと＋タブが手前に戻ったとき（ADR-0044 と同じ）。
- `sw-migration.js` は外す（待機させないので移行の問題が起きない）。

## 理由

- 「リロードすれば新しくなる」はウェブの当たり前で、説明が要らない。
- 黙って再読み込みはしない。入力の途中の内容が消える。知らせは押すまで残す。
- 画面は 1 本の JavaScript で、後から読み込む部品が無い。古い画面が新しい Service Worker の
  下で動き続けても、取りに行く古いファイルが無いので壊れない。

## 影響

- 初めて開いた画面が制御されるときの合図は知らせない（新しい版ではないため）。
- ADR-0044 のときに付けた印（Cache Storage の `rewardpoints-update-prompt-v1`）は空のまま残るが、使わない。
