# ADR-0025: 家族まるごとの控え（バックアップと復元）

- 日付: 2026-08-09
- 状態: 承認

## 文脈

台帳は追記専用（ADR-0010）で、記録は消さずに積み上がる。積み上がるからこそ、
**DB を失うと取り返しがつかない**。数年分のポイントの履歴は、思い出として
残しておきたいものでもある。

これまで、利用者が自分の家族のデータを手元へ取り出す道が無かった。DB のバックアップ
はホストの運用者にはできるが、

- 家族の当事者（親）が自分で取れない
- MariaDB のダンプは家族単位で切り出せない（他の家族も一緒に入る）
- 別のホストへ引っ越したいだけのときも、DB まるごとの復元しか手が無い

という状態だった。

## 決定

**家族 1 つを 1 つの JSON ファイルへ書き出し、そこから作り直せるようにする。**

- `GET /api/families/{id}/export` — 家族・参加者・子どもの台帳・記録・毎日の
  ボーナスを 1 つの入れ子で返す（親のみ）。
- `POST /api/families/import` — その JSON から **新しい家族** を作り、呼んだ人が
  owner になる。

書き出した JSON をそのまま送り返せば元に戻る（往復できる）ことを、この形の
唯一の基準とする。

## 理由

**なぜ家族単位か。** 家族はもともとデータ分離の境界（ADR-0009）で、台帳も参加者も
必ずどれか 1 つの家族に属する。ここで切れば、他の家族を巻き込まずに一貫した塊を
取り出せる。台帳 1 つ（子ども 1 人分）だと、記録した人の名前も並び順も家族側に
あるので、そこだけ切り出しても復元できない。

**なぜアカウントを載せないか。** 控えは利用者の手元へ落ちる。ログイン ID・パス
ワード・招待コードが入っていれば、ファイルを拾った人が家族の中に入れてしまう。
アカウントは家族の持ち物ではない（このコンテキストの外にある）ので、載せない
ことで控えの値打ちが下がることもない。復元した家族に本人が入り直す道は招待コード
（ADR-0011）で、もともと用意されている。

**なぜ DB の ID ではなく `ref` か。** 復元先では ID が全部変わる。「誰が記録したか」
「どの記録の打ち消しか」を DB の ID で書けば、別のインスタンスへ持ち込んだ時点で
必ず食い違う。ファイルの中だけで通じる名前（`m1` / `t1`）にすると、繋がりは
どこへ持って行っても保たれる。

**なぜ既存の家族へ混ぜないか。** 同じ名前の子が控えと今の家族の両方にいるとき、
どちらが同じ子かを決められるのは人だけで、機械が選ぶと台帳が静かに二重になる。
取り込みを「新しい家族を作る」に限れば、混ざりようがない。今の家族を控えの状態へ
戻したい場合は、解散してから取り込む（記録の残る家族は解散できない
（ADR-0013）ので、意図せず消える経路にはならない）。

**なぜ CSV ではないか。** 打ち消しと訂正（ADR-0022）は行どうしの繋がりで、表に
すると失われる。繋がりが失われた控えから復元すると、履歴の「打ち消し済み」の印が
消え、打ち消した記録をもう一度打ち消せてしまう。

**なぜ `version` を持つか。** 形が変わったとき、読めない項目を黙って捨てると
「復元したつもりで記録が減っている」ことに気付けない。読めない版は断る。

**なぜ取り込みでも台帳の決まりを検査するか。** 控えはファイルなので、人が手で
書き換えられる。打ち消しの打ち消し・二重の打ち消し・逆符号でない打ち消しを
そのまま書ければ、API を通しては作れない台帳が DB に入る。同じ決まりを取り込みの
入口でも守る（`family_archive_rules`）。

## 影響

- **owner 以外はアカウント未紐付けで戻る。** 復元した親・子は誰もログインできない
  状態なので、招待コードを配り直す。子は台帳ごと戻るので、招待を受けた時点で
  自分の履歴が残っている。
- 招待は戻ってきた参加者を **指して** 配る（画面の「〇〇 の招待コード」）。指さずに
  新しく入れ直すと参加者が 1 人増え、台帳の「記録した人」は未紐付けのまま残った
  古い方を指し続ける。指せる相手はもともと未紐付けの子だけだったので、未紐付けの
  親も並べるようにした（親宛のコードを配れるのは owner だけ — ADR-0020）。
- **記録された日時（`created_at`）は取り込んだ時刻になる。** 出来事の日時
  （`occurred_at`）は控えのものを使う。行が今この DB へ書かれたことは事実で、
  そこは偽らない。
- **毎日のボーナスの `granted_through` も控える。** 落とすと、復元した直後に
  「まだ渡していない日」が開始日まで遡って復活し、控えに入っている日のボーナスが
  もう一度足される（ADR-0024 の追いつき）。
- **未使用の招待は控えに入らない。** コードのハッシュを持ち出しても復元先では
  意味を成さない。
- 冪等キーは控えの `ref` から作り直す（`import-t1`）。書き出し元のキーは
  「同じ要求が二度届いたか」を見るための鍵で、別の台帳へ運ぶ意味がない。
- 取り込みは 1 リクエストで台帳へ大量に書く。上限は Presentation 層のスキーマで
  持つ（参加者 100・記録 20,000）。
- 形を変えるときは `ARCHIVE_VERSION` を上げ、古い版の読み方を残すか、断るかを
  決める。
