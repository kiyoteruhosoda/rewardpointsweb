# ADR-0044: 新しい版は知らせるだけで、入れ替えるのは利用者が押したとき

- 日付: 2026-10-03
- 状態: 廃止（ADR-0045 で置き換え）

## 文脈

これまでは `registerType: 'autoUpdate'` だった。新しい Service Worker は黙って有効に
なるが、**開いている画面の JavaScript は差し替わらない**。ホーム画面に置いたアプリを
開きっぱなしにしていると、配った後も古い画面のまま使い続けることになり、新しい機能
（イベント等）が「出ない」と見える。

## 決定

- `registerType: 'prompt'` にし、新しい版が待機したら画面の下に「新しい版があります。
  ［再読み込み］」を出す。入れ替えるのは押したとき。
- 更新の確認は自分で起こす（30 分ごと、タブが手前に戻ったとき。オフライン・取得中・
  直前に確認済みは飛ばす）。
- 押した後 2 秒経っても入れ替わらなければ、自前で再読み込みする。
- 作りは雛形（fastapitemplate の ADR-0035）と同じ。

## 理由

- SPA の画面切り替えはページ遷移ではないので、ブラウザは Service Worker の更新を確認しない。
  待つだけでは知らせが出ない。
- まだ Service Worker に制御されていないタブ（初めて開いた直後）では、制御が移った合図
  （`controllerchange`）が来ない。押しても何も起きない取りこぼしを、2 秒後の再読み込みで拾う。
- 知らせはトーストにしない。数秒で消えると、見ていない間に出て消える。
- 黙って再読み込みはしない。入力の途中で画面が入れ替わると、打った内容が消える。

## 影響

- 画面の下に版の知らせが出ることがある（押すまで残る）。
- 版の表記から `v` を外した（`scripts/generate_version.sh` は `695ff03`、main 以外は
  `695ff03-<枝>`）。フッターは SHA と同じなら 1 度だけ出す。

## 追記（2026-10-03）: 前の作りからの移行は一度だけ待たずに入れ替える

`prompt` へ切り替えた版（`b4ec96e`）を配ったところ、**前の作り（autoUpdate）の画面が古いまま止まった**。
前の作りの画面は「待機した Service Worker を入れ替える」合図を送らない（新しい Service Worker が自分で
`skipWaiting` する前提の作り）ので、新しい版は端末のアプリを完全に閉じるまで待機し続ける。

`public/sw-migration.js` を `importScripts` で sw.js に読み込み、**知らせる作りの Service Worker が一度でも
有効になったか**を Cache Storage の名前（`rewardpoints-update-prompt-v1`）で覚える。印が無いとき——前の
作りから移るとき——だけ `skipWaiting` する。前の作りの画面は有効化を受けて自分で再読み込みする。印が
付いた後の更新は待機し、画面が知らせを出す。

⚠ `b4ec96e` を初めて開いた端末（知らせる作りの画面）も、この版へは一度だけ黙って入れ替わる
（印が無いため）。その画面は次に開いたときから新しくなり、以後の更新は知らせが出る。
