# ADR-0046: サーバーに届かないことを、ログアウトとして扱わない

- 日付: 2026-10-04
- 状態: 承認
- 関連: fastapitemplate ADR-0050（雛形の同じ決定）/ toeic ADR-0054 / 課題 task.nolumia.com #249

## 文脈

リリースのあいだ、アプリは 1〜2 分ほど応答しない（edge が 503 を返す）。画面の殻は Service Worker が
持っているので開けるが、API は届かない。雛形から受け継いだ画面では次の 2 つが重なり、派生アプリ（toeic）で
持ち主が「リリースするとログイン画面が出るが、SSO のリンクが無い」状態に取り残された。

1. `/api/auth/me` が失敗すると、理由を問わずトークン（とオフライン閲覧のキャッシュ。ADR-0015）を消し、
   未ログインとみなしてログイン画面へ送る
2. ログイン画面は SSO の問い合わせ（`/api/auth/sso/provider`）に一度失敗すると諦めて、SSO のボタンを出さない。
   サーバーが戻ってもボタンは出ないまま

## 決定

- `/api/auth/me` が **4xx なら未ログイン**、**5xx・通信の失敗なら「届かない」**として分ける。届かないときは
  ログイン画面へ送らず「サーバーにつながりません（新しい版を配っている最中かもしれません）」を出し、
  5 秒ごとに聞き直す（`store/AuthContext.tsx` の `unreachable`・`RECONNECT_INTERVAL_MS`）
- 届かないときは**トークンもオフライン閲覧のキャッシュも消さない**（ログアウトではない）
- ログイン画面は、SSO の問い合わせが届かなければ同じ文言を出し、5 秒ごとに聞き直す。つながったら SSO の
  ボタンを出す。⚠ **パスワードの欄は出したままにする** ——このアプリではパスワードが主な入口で（SSO は任意）、
  雛形（入口が分かるまで何も出さない）とはここだけ違えた

## 理由

- サーバーに届かないとき、どの入口を出しても押せば失敗する。出しておく意味が無く、出した既定の欄が
  サーバーが戻ったあとまで残るのが害だった
- 未ログインの答え（401）は届いたサーバーが返すもので、5xx・通信の失敗とは見分けられる

## 影響

- サーバーが長く落ちたままなら、画面は「つながりません」を出し続ける（ログイン画面へは送らない）
