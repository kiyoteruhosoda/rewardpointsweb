# ADR-0057: DB を使う口と依存関数は def で書く

- 日付: 2026-10-31
- 状態: 承認（task #807。雛形 fastapitemplate の ADR-0100 を取り込む）

## 文脈

口の多くが `async def` で、SQLAlchemy の呼び出しは同期だった。同じ行を書く要求が同じプロセスで重なると、後の要求がイベントループの上でロックを待ち、先の要求の確定が走らない。MariaDB のロック待ちの上限か gunicorn の `--timeout` まで全部の要求が止まり、書き込みも失われる。SQLite の試験では出ない。

## 決定

1. **DB に届く口と依存関数は `def` で書く。** FastAPI がスレッドプールで動かすので、待つのはそのスレッドだけになる。
2. **DB に届かない `async def` はそのまま。** `/healthz` はスレッドプールが埋まっても答える必要がある。
3. **ログと監査の文脈（`ContextVar`）を置く依存関数は `async def` のまま。** スレッドの中で置いた値は呼び出し元へ戻らず、「誰が」が黙って消える。
4. **`await` が要る口は `async def` のまま、DB を `run_in_threadpool` へ逃がす。**
5. **試験で止める**（`tests/integration/api/test_event_loop_stays_free.py`。例外は理由と一緒に表へ）。

採らなかった案と理由は雛形の ADR-0100 にある（非同期版の SQLAlchemy へ移す、その場で確定する、など）。

## 影響

同じプロセスの中で要求が同時に DB を使えるようになる。接続は既定で 1 プロセス 15 本で、接続を待つ要求は 30 秒で 500 になることがある。口の本体がプロセスのグローバルな値を読み書きするときは、スレッドで動く前提で書く。
