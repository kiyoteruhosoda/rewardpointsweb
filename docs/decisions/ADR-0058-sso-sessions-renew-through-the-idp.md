# ADR-0058: SSO で入ったログインはリフレッシュトークンを持たず、切れたら画面を出さずに IdP へ問い合わせる

- 日付: 2026-11-05
- 状態: 承認
- 関係: ADR-0029（引き換え券）・ADR-0032（IdP からの停止）・ADR-0037（検証は DB を引かない）・ADR-0047（表示端末）・ADR-0052（ログイン画面の prompt=none）。nolumiawiki の ADR-0118 と同じ形。雛形 fastapitemplate の ADR-0104 を、このアプリの形に合わせて写したもの（task #888・#889）。**パスワード・パスキーで入ったログインには何も変えない**

## 文脈

assay のログイン状態は、結び付けの有無で長さが変わり、端末の登録を取り消すと終わる（task #875・#887・#872）。ところがこのアプリは SSO で入ったあと、自分でリフレッシュトークンを持つ。画面の `localStorage` をまとめて盗まれると、assay のログイン状態が終わっても、アプリのリフレッシュトークンからその寿命の間使われる（task #888）。雛形は ADR-0104 で、SSO で入ったログインからリフレッシュトークンを外した。

このアプリは雛形と作りが違い、そのままは写せない。

- **トークンは画面の `localStorage` に持ち、`Authorization` ヘッダーで送る**（雛形は httpOnly の Cookie）。戻りが Cookie を載せても画面は使えない。
- **往復の控えはサーバーの表 `sso_login_sessions` に置き、ブラウザには合言葉の Cookie だけ**（雛形は署名付きの Cookie に往復状態を入れる）。
- **リフレッシュトークンは本文で受け渡す**（`POST /api/auth/refresh` の `refresh_token`）。
- **アクティブロールを持たない**（有効な scope は全ロールの和集合）。続けるときに引き継ぐものは無く、同じ人かだけを見る。
- **表示端末**（ADR-0047）は端末の資格情報で 5 分のトークンを取り直す。SSO とは別の道なので変えない。

## 決定

1. **SSO で入ったログインには、リフレッシュトークンを出さない**（応答の `refresh_token` は `null`、画面は `localStorage` から消す）。出すのはアクセストークン（`ACCESS_TOKEN_EXPIRES_SECONDS`。既定 5 分）だけ。
2. **この仕組みより前に出した SSO のリフレッシュトークンは、更新の口で断る**（401 `invalid_token`）。
3. **切れたら、画面が見えない枠（iframe）で `GET /api/auth/sso/renew` を開く。** そこから IdP へ `prompt=none` で往復する。控え（`sso_login_sessions`）に **`renewal` の印**（新しい列）を付け、戻り（`/callback`）はこの印で続ける往復と見分ける。
4. **続けられたら、戻りは結果の頁へ 1 回限りの引き換え券を付けて送る**（`/api/auth/sso/renewed?result=renewed&ticket=…`）。画面は枠の行き先（同じオリジン）から券を読み、`POST /api/auth/sso/token` に `continuing: true` と**手元の（期限切れの）アクセストークン**を添えて換える。券はログインの戻り（`/login/sso?ticket=…`）と同じもので、1 回限り・短命・ハッシュで保存。
5. **同じ人のときだけ続ける。** `continuing` の引き換えでは、添えたトークン（署名・発行者・宛先を確かめ、期限は 30 日まで見逃す。`RENEWAL_CARRY_SECONDS`）の利用者と券の利用者が**同じときだけ**換える。**別の人なら 401 `sso_renewal_switched_user`**（IdP で別の人に入り直していた。開いている画面は前の人のもの）。読めなければ新しいログインとして入る。ふつうのログイン（`continuing` なし）は添えたトークンを見ない。
6. IdP の「入っていない・許可が無い」は `declined`。往復が壊れた・IdP と話せない・時間切れ（15 秒）は `failed`。どちらも画面はログイン画面へ送る（行き先は `redirect_to`）。
7. **枠に入れてよいのは自分のオリジンだけ。** `/renew`・続ける往復の `/callback`・結果の頁は `X-Frame-Options: SAMEORIGIN` と `frame-ancestors 'self'`。結果の頁は何も読み込まず `Referrer-Policy: no-referrer`・`Cache-Control: no-store`。
8. **続ける往復はタブをまたいで 1 本ずつ**（Web Locks。合言葉の Cookie は 1 つ）。待つ間にほかのタブが続けていれば（`/api/auth/me` が通れば）枠を開かない。
9. **入口の 401（パスワード違い・二要素の不足など）では続けない。** 続けるのは `authentication_required` と `invalid_token` の 401 だけ。サインアウトした印があるときも問い合わせない。断られたらこのタブの「試した」印を付け、ログイン画面の自動の試し（ADR-0052）を重ねない。
10. **書きかけ**: 家族・子ども・イベント・ロール・ユーザーの追加の欄は `useSessionValue`（sessionStorage）に写す。パスワードの欄は残さない。サインアウトで消す。
11. このアプリに監査ログは無い。アプリログに `sso_renewal_succeeded`・`sso_renewal_declined` などを残す（利用者を作った・結び付けたことは今までどおり）。
12. IdP からの停止の記録を残す長さは、リフレッシュトークンの期間とアクセストークンの寿命の長いほう。

## 理由

- **何を塞ぐか**: 画面の `localStorage` を盗まれても、5 分を過ぎると IdP のログイン状態（結び付け・端末の登録・取り消し）に従う。
- **券を結果の頁に載せる**: トークンは画面が持つので、戻りに Cookie を載せても使えない。券なら、今のログインの戻りと同じ「1 回限りの券 → 画面が換える」の道をそのまま使え、トークンを URL に載せない（ADR-0029）。枠の URL は画面からしか読めない（同じオリジン）。
- **控えに `renewal` の列を足す**: 目的をクエリで渡すと、戻りの URL を書き換えるだけで化けさせられる。控えは既にサーバーにあるので、印を 1 つ足すのが最も小さい。
- **同じ人かは引き換えで確かめる**: 画面が添えるトークンは署名付きなので改竄できない。往復の控えに利用者を写す（雛形の形）より、既にある引き換えの口で見るほうが変更が小さい。
- **nolumiawiki と同じ形にする**: 2 本ともトークンを `localStorage` に持ち、往復の控えを表に置く（雛形より前の作り）。同じ口・同じ結果の頁なら直しを揃えて追える。

| 採らなかった案 | 捨てた理由 |
|---|---|
| 雛形と同じく戻りで Cookie を載せる | 画面は `localStorage` のトークンで送るので使えない。トークンの持ち方ごと Cookie へ移すのはこの課題の外 |
| 枠をログインの戻り（`/login/sso?ticket=…`）へ着かせる | 枠の中で SPA が丸ごと起き、自分でも券を換え・SSO を試す |
| 結果の頁から `postMessage` で返す | 頁にスクリプトが要る |
| リフレッシュトークンを短くする | 盗まれてからその長さは使われる。IdP の取り消しも効かない |

## 影響

- SSO で入ったログインの長さは IdP のログイン状態で決まる（`REFRESH_TOKEN_EXPIRES_SECONDS` は SSO には効かない）。画面を閉じていた間に IdP のログイン状態が終わっていれば、開いた時点でログイン画面になる。
- 配った直後、画面に前の仕組みの refresh トークンが残っている人は、次の 401 で更新を断られてトークンを消され、ログイン画面の自動の試し（ADR-0052）で入り直す（IdP で入っていればボタンは要らない）。
- 止めた記録（`federated_session_revocations`）は更新の口でしか見ていない。SSO で入ったログインは更新しないので、止まったかは IdP が次の問い合わせ（5 分以内）で決める。
- マイグレーション `renewal_round_trip`（列を足すだけ）。本番は起動時に当たる。
- IdP（assay）が `prompt=none` の往復を `*.nolumia.com` の枠の中で通すこと（idp の ADR-0076・`SILENT_AUTH_FRAME_ANCESTORS`）が前提。枠がブラウザに止められても、401 のあとログイン画面の自動の試しで全画面の往復になる。
